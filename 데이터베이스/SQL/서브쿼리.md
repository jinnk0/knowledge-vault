서브쿼리(Subquery)는 하나의 [[데이터베이스/SQL/SQL.md|SQL]]문 안에 포함된 또 다른 SELECT 문이다. 서브쿼리를 포함하는 바깥쪽 쿼리를 메인쿼리라고 한다. 서브쿼리는 [[데이터베이스/SQL/SELECT/SELECT.md|SELECT]] 절, FROM 절, [[데이터베이스/SQL/SELECT/WHERE 절.md|WHERE 절]], [[데이터베이스/SQL/SELECT/GROUP BY 절.md|HAVING 절]], [[데이터베이스/SQL/SELECT/ORDER BY 절.md|ORDER BY 절]] 등에서 사용할 수 있다.

```sql
SELECT 이름, 급여
FROM 사원
WHERE 급여 > (SELECT AVG(급여) FROM 사원);  -- 괄호 안이 서브쿼리
```

## 사용 시 주의사항

- 서브쿼리는 괄호로 감싸서 사용한다.
- 서브쿼리는 단일 행 비교 연산자 또는 복수 행 비교 연산자와 함께 사용할 수 있다. 서브쿼리가 복수 행 결과를 반환하는 경우에는 IN, ALL, ANY 등의 복수 행 비교 연산자와 함께 사용해야 한다.
- 서브쿼리에서는 ORDER BY를 사용하지 못한다. ORDER BY는 전체 SELECT 문에서 오직 하나만 올 수 있기 때문이다. 단, FROM 절에 쓰는 인라인 뷰는 예외로 ORDER BY를 쓸 수 있다.

## 메인쿼리와의 관계에 따른 분류

서브쿼리는 메인쿼리의 컬럼을 참조하느냐에 따라 두 가지로 나뉜다.

- **연관(Correlated) 서브쿼리**: 서브쿼리가 메인쿼리의 컬럼을 포함하고 있는 형태의 서브쿼리다.
- **비연관 서브쿼리**: 메인쿼리의 컬럼을 포함하지 않는 서브쿼리로, 주로 메인쿼리에 값을 제공하기 위한 목적으로 사용한다.

```sql
-- 비연관 서브쿼리: 서브쿼리가 먼저 전체 평균을 구해 메인쿼리에 제공한다
SELECT 이름 FROM 사원
WHERE 급여 > (SELECT AVG(급여) FROM 사원);

-- 연관 서브쿼리: 메인쿼리의 행(A.부서번호)마다 서브쿼리가 다시 계산된다
SELECT 이름 FROM 사원 A
WHERE 급여 > (SELECT AVG(급여) FROM 사원 B WHERE B.부서번호 = A.부서번호);
```

이처럼 메인쿼리의 결과가 서브쿼리로 제공될 수도 있고, 서브쿼리의 결과가 메인쿼리로 제공될 수도 있으므로, 실행 순서는 상황에 따라 달라진다.

## 반환 데이터 형태에 따른 분류

서브쿼리는 반환하는 데이터의 형태에 따라 세 가지로 나뉜다.

| 종류 | 반환 결과 | 함께 쓰는 연산자 |
|---|---|---|
| Single Row 서브쿼리 (단일 행 서브쿼리) | 항상 1건 이하 | 단일 행 비교 연산자 (=, >, >=, <, <=, <>) |
| Multi Row 서브쿼리 (다중 행 서브쿼리) | 여러 건 | 다중 행 비교 연산자 (IN, ALL, ANY, SOME, EXISTS) |
| Multi Column 서브쿼리 (다중 컬럼 서브쿼리) | 여러 컬럼 | 메인쿼리 조건절에서 여러 컬럼을 동시에 비교 |

- **Single Row 서브쿼리**: 서브쿼리의 실행 결과가 항상 1건 이하인 서브쿼리로, 단일 행 비교 연산자와 함께 사용한다.
- **Multi Row 서브쿼리**: 서브쿼리의 실행 결과가 여러 건인 서브쿼리로, IN, ALL, ANY, SOME, EXISTS 같은 다중 행 비교 연산자와 함께 사용한다.
- **Multi Column 서브쿼리**: 서브쿼리의 실행 결과로 여러 컬럼을 반환하므로, 메인쿼리의 조건절에서 여러 컬럼을 동시에 비교할 수 있다. 서브쿼리와 메인쿼리에서 비교하고자 하는 컬럼의 개수와 위치가 동일해야 한다. SQL Server에서는 지원하지 않는 기능이다.

```sql
-- Multi Row 서브쿼리: 서브쿼리 결과가 여러 건이므로 = 대신 IN을 쓴다
SELECT 이름 FROM 사원
WHERE 부서번호 IN (SELECT 부서번호 FROM 부서 WHERE 지역 = '서울');

-- Multi Column 서브쿼리: (부서번호, 급여) 두 컬럼을 같은 순서로 비교한다
SELECT 이름 FROM 사원
WHERE (부서번호, 급여) IN (SELECT 부서번호, MAX(급여) FROM 사원 GROUP BY 부서번호);
```

## 위치에 따른 분류

서브쿼리는 쓰이는 위치에 따라 이름이 다르다.

| 위치 | 이름 | 반환 | 쓰임 |
|---|---|---|---|
| SELECT 절 | 스칼라 서브쿼리 | 1행 1컬럼 | 컬럼처럼 사용 |
| FROM 절 | 인라인 뷰 (= 다이나믹 뷰) | 여러 행·여러 컬럼 | 테이블처럼 사용 |
| WHERE 절 | 일반 서브쿼리 (중첩 서브쿼리) | 단일 행 또는 다중 행 | 조건 비교 |

### 스칼라 서브쿼리

스칼라 서브쿼리는 SELECT 절에 쓰는 서브쿼리로, 정확히 1행 1컬럼(단일 값)을 반환해야 한다. 결과는 컬럼처럼 취급된다.

```sql
SELECT A.사원명,
       (SELECT B.부서명 FROM 부서 B WHERE B.부서번호 = A.부서번호) AS 부서명
FROM 사원 A;
```

위 쿼리는 사원마다 해당 부서명을 하나씩 가져온다. 이처럼 [[데이터베이스/SQL/조인.md|조인]] 대신 쓸 수 있는 방식이다.

- 결과가 2행 이상이면 오류가 나고, 0행이면 [[데이터베이스/NULL.md|NULL]]이 된다.
- 위 예시처럼 바깥 쿼리의 값을 참조하는 연관 서브쿼리 형태가 많다.

### 인라인 뷰

인라인 뷰는 FROM 절에 쓰는 서브쿼리로, 그 결과를 하나의 테이블처럼 사용한다. 다이나믹 뷰(Dynamic View)라고도 부른다.

```sql
SELECT D.광고매체ID, D.시작일
FROM (SELECT 광고매체ID, MIN(광고시작일자) AS 시작일
      FROM 광고게시
      GROUP BY 광고매체ID) D;  -- 괄호 안의 결과를 D라는 테이블처럼 사용
```

- 일반 뷰는 `CREATE VIEW`로 DB에 저장되지만, 인라인 뷰는 쿼리를 실행하는 순간에만 존재한다. 그래서 "동적(Dynamic)" 뷰라고 부른다.
- 별칭(위 예시의 D)을 붙여서 사용한다.
- 다른 서브쿼리와 달리 안에서 ORDER BY를 쓸 수 있어서, 정렬한 뒤 상위 N건만 뽑는 Top-N 쿼리에 자주 쓰인다.
- 인라인 뷰 안의 컬럼은 바깥 쿼리에서 참조할 수 있다. WHERE 절의 일반 서브쿼리는 메인쿼리가 그 안의 컬럼을 쓸 수 없지만, 인라인 뷰는 반대 방향의 참조가 가능하기 때문에 메인쿼리의 SELECT 절에서 인라인 뷰의 컬럼을 쓸 수 있다.
