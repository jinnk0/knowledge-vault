함수 종속성(Functional Dependency)은 데이터베이스 릴레이션(테이블)에서 특정 속성(들)의 값에 의해 다른 속성의 값이 고유하게 결정되는 제약 조건이다. [[데이터베이스/데이터 모델링/데이터 모델링.md|데이터 모델링]]에서 [[데이터베이스/데이터 모델링/정규화.md|정규화]]를 수행하는 기준이 된다.

## 결정자와 종속자

속성 X의 값이 속성 Y의 값을 결정할 때 이를 X → Y로 표기하고, X를 결정자(Determinant), Y를 종속자(Dependent)라고 한다. 예를 들어 학번을 알면 학생 이름이 하나로 정해지므로 학번 → 이름이 성립한다.

결정자가 테이블의 모든 속성을 결정할 수 있으면 그 결정자는 슈퍼키가 되고, 슈퍼키 중 최소성을 만족하는 결정자가 후보키가 된다. 슈퍼키와 후보키의 자세한 조건은 [[데이터베이스/데이터 모델링/키.md|키]] 노트에서 다룬다.

## 종류

함수 종속은 종속자가 어떤 방식으로 결정되느냐에 따라 세 가지로 나뉜다.

| 종류 | 설명 |
|---|---|
| 완전 함수 종속 (Full Functional Dependency) | 종속자가 기본키(Primary Key) 전체에 종속되는 경우 |
| 부분 함수 종속 (Partial Functional Dependency) | 복합 기본키를 구성하는 속성 중 일부 속성에만 종속되는 경우 |
| 이행 함수 종속 (Transitive Functional Dependency) | X → Y이고 Y → Z일 때, 유추에 의해 X → Z가 성립하는 경우 |

기본키가 (학번, 과목코드)인 수강 테이블을 예로 들어 보자. 성적은 학번과 과목코드를 모두 알아야 정해지므로 기본키 전체에 완전 함수 종속한다. 반면 학생 이름은 학번만 알아도 정해지므로 기본키의 일부에만 부분 함수 종속한다.

이행 함수 종속은 기본키가 아닌 속성끼리의 종속에서 생긴다. 기본키가 학번인 학생 테이블에 학과와 학과장이 함께 있다면, 학번 → 학과이고 학과 → 학과장이므로 학번 → 학과장이 유추된다.

## 정규화의 기준

함수 종속성은 정규화의 기준이 된다. 삽입·갱신·삭제 이상 같은 이상 현상을 제거하고 데이터 중복을 최소화하기 위해, 테이블의 함수 종속성을 분석해 1NF, 2NF, 3NF, BCNF 등의 정규형으로 데이터를 분해한다. 부분 함수 종속을 제거하면 제2정규형이 되고, 이행 함수 종속을 제거하면 제3정규형이 된다.
