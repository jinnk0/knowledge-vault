[[복잡도/복잡도.md|복잡도]]의 한 종류인 시간 복잡도(Time Complexity)는 알고리즘이 실행되는 데 걸리는 시간을 입력 길이에 대한 함수로 나타낸 것이다.

같은 문제를 해결하는 방법(알고리즘)은 여러 가지일 수 있고, 방법마다 걸리는 시간과 사용하는 공간, 필요한 연산량이 다르다. 그래서 이 접근 방식들을 비교해서 가장 효율적인 것을 고를 방법이 필요하다. 실행 시간을 기준으로 비교하고 싶어도, 서로 다른 언어로 작성되어 서로 다른 머신에서 실행되는 알고리즘은 실제 걸린 시간만으로는 비교하기 어렵다. 시간 복잡도는 이런 문제를 해결하기 위해 도입된 개념이다.

## 중요성

시간 복잡도가 중요한 이유는 다음과 같다.

- 효율성을 기준으로 서로 다른 두 알고리즘을 명확하게 구분할 수 있다.
- 알고리즘이 실행되는 머신과 무관하게 비교할 수 있다.
- 입력 길이와 직접적인 상관관계를 파악할 수 있다.

시간 복잡도는 알고리즘이 실행되는 실제 시간을 측정하는 것이 아니다. 실제 걸리는 시간은 프로그래밍 언어나 처리 능력 등 실행 환경에 따라 달라지기 때문이다. 시간 복잡도는 그런 환경 요인과 무관하게, 알고리즘과 입력값 자체의 관점에서 실행 시간을 계산한다.

## 계산 방법

컴퓨터의 아키텍처(32비트 또는 64비트), 단일 또는 다중 프로세서 여부, 읽기·쓰기 속도, 시스템 구성, 입력값 등 다양한 요인에 따라 알고리즘의 실제 실행 시간은 달라질 수 있다. 하지만 이를 단순화하기 위해 입력값만 변수로 두고 나머지 요인은 상수로 고정한다. 기본적으로 단일 프로세서, 32비트, 순차적 실행, 산술·논리 연산에 1단위 시간이 걸리는 시스템을 가정한다.

입력값의 함수로서 프로그램의 실행 시간을 $T(n)$이라 하면, 다음과 같은 연산은 $T(n) = 1$이다.

- 대입 연산자 / return문 (예: `int a = 10`)
- 산술 연산 (`+`, `-`, `*`, `/`)
- 논리 연산 (`&`, `|`, `^`)

크기가 $n$인 리스트의 합을 구하는 다음 함수를 예로 들면,

```
sum(list, size of list):
    total = 0                   ----> T(n) = 1
    for i -> 0 to size of list  ----> T(n) = n + 1
        total += list[i]        ----> T(n) = n
    return total                ----> T(n) = 1
```

전체 실행 시간은 $T(n) = 1 + 2(n+1) + 2n + 1 = 4n + 4$로 선형(Linear)이다. 같은 방식으로 행렬의 합을 구하면 이중 루프가 필요하므로 실행 시간은 이차(Quadratic) 형태가 된다.

### 최선과 최악의 경우

입력에 어떤 값이 들어 있는지 모르는 경우, 실행 시간은 하나로 정해지지 않고 최선의 경우(Best case)와 최악의 경우(Worst case)로 나뉘어 측정된다. 배열에서 값 1을 찾는 다음 함수가 그 예다.

```cpp
bool Find_One(arr[], int n)
{
   for (int i = 0; i < n; i++)
      if (arr[i] == 1)
      {
          return true;
      }
   return false;
}
```

- **최선의 경우**: 배열의 첫 번째 요소가 1이면 곧바로 반환되므로 상수 시간이 걸린다.
- **최악의 경우**: 배열에 1이 없으면 배열 전체를 순회해야 하므로 선형 시간이 걸린다.

이렇게 최선과 최악의 경우를 구분해서 표현하는 방법이 [[복잡도/시간 복잡도/점근적 표기법.md|점근적 표기법]](Asymptotic Notation)이다. 배열의 첫 위치에 값이 있을 때는 상수 시간, 마지막 위치에 있거나 아예 없을 때는 선형 시간이 걸리는 것처럼 같은 알고리즘도 입력에 따라 실행 시간이 달라질 수 있기 때문에, 빅오(최악), 빅오메가(최선), 빅세타(평균) 세 가지 표기법으로 나누어 설명한다.

## 복잡도 등급

일반적인 알고리즘의 실행 시간을 가장 빠른 순에서 가장 느린 순으로 나열하면 다음과 같다.

| 표기법 | 명칭 | 예시 |
|---|---|---|
| $O(1)$ | 상수 시간 복잡도 (Constant) | 두 수의 합 구하기 |
| $O(\log n)$ | 로그 시간 복잡도 (Logarithmic) | 이진 탐색으로 정렬된 배열에서 요소 찾기 |
| $O(n)$ | 선형 시간 복잡도 (Linear) | 크기가 $n$인 배열의 총합 구하기 |
| $O(n \log n)$ | 선형 로그 시간 복잡도 (Log-Linear) | 병합 정렬로 배열 정렬하기 |
| $O(n^2)$ | 이차 시간 복잡도 (Quadratic) | 배열 내 모든 쌍의 합 구하기 |
| $O(2^n)$ | 지수 시간 복잡도 (Exponential) | 모든 부분집합 구하기 |
| $O(n!)$ | 팩토리얼 시간 복잡도 (Factorial) | 배열의 모든 순열 구하기 |

입력 크기 $n$이 커질수록 각 등급의 실행 시간이 얼마나 빠르게 벌어지는지는 다음 그래프로 확인할 수 있다.

정렬·탐색 알고리즘별 최선/평균/최악의 시간 복잡도를 정리하면 다음과 같다.

| 알고리즘 | 최선 | 평균 | 최악 |
|---|---|---|---|
| 선형 탐색(Linear Search) | $O(1)$ | $O(n)$ | $O(n)$ |
| 이진 탐색(Binary Search) | $O(1)$ | $O(\log n)$ | $O(\log n)$ |
| 버블 정렬(Bubble Sort) | $O(n)$ | $O(n^2)$ | $O(n^2)$ |
| 선택 정렬(Selection Sort) | $O(n^2)$ | $O(n^2)$ | $O(n^2)$ |
| 삽입 정렬(Insertion Sort) | $O(n)$ | $O(n^2)$ | $O(n^2)$ |
| 병합 정렬(Merge Sort) | $O(n \log n)$ | $O(n \log n)$ | $O(n \log n)$ |
| 퀵 정렬(Quick Sort) | $O(n \log n)$ | $O(n \log n)$ | $O(n^2)$ |
| 힙 정렬(Heap Sort) | $O(n \log n)$ | $O(n \log n)$ | $O(n \log n)$ |
| 버킷 정렬(Bucket Sort) | $O(n+k)$ | $O(n+k)$ | $O(n^2)$ |
| 기수 정렬(Radix Sort) | $O(nk)$ | $O(nk)$ | $O(nk)$ |
| 팀 정렬(Tim Sort) | $O(n)$ | $O(n \log n)$ | $O(n \log n)$ |
| 셸 정렬(Shell Sort) | $O(n)$ | $O((n \log n)^2)$ | $O(n^2)$ |

## 복잡도 계산 규칙

시간 복잡도를 계산할 때는 입력 크기가 매우 크다고 가정한다는 점을 항상 기억해야 한다. 이를 바탕으로 다음 세 가지 규칙을 적용하면 복잡한 계산도 단순화할 수 있다.

**규칙 1: 상수 곱하기(계수)는 무시한다.** 예를 들어 $T(n) = 3n^3$의 최악의 경우 실행 시간은 상수 항 3을 제거한 $O(n^3)$이다.

**규칙 2: 낮은 차수의 항은 무시한다.** $T(n) = 3n^2 + 2n\log n + 5n + 4$가 주어졌다면 가장 차수가 높은 항은 $3n^2$이므로 나머지 항을 제거하고, 규칙 1을 다시 적용해 $O(n^2)$로 정리한다.

**규칙 3: 프로그램의 실행 시간은 모든 조각(Fragment)의 실행 시간의 합이다.** 다음 프로그램을 예로 들면,

```cpp
// 조각 1
for (int i = 0; i < n; i++)
{
    int a = 5;
    a++;
}

// 조각 2
for (int i = 0; i < n; i++)
{
   for (int j = 0; j < n; j++)
   {
       int b = 5;
       b++;
   }
}
```

첫 번째 루프(조각 1)와 이중 루프(조각 2)로 나눌 수 있다. 선언·대입·산술 연산 같은 단순 문장의 실행 시간은 $O(1)$이므로, 조각 1은 $n$번 반복되어 $O(n)$, 조각 2는 $O(n^2)$이 된다. 따라서 전체 시간 복잡도는 $O(n) + O(n^2) = O(n^2)$이다.

## 예시

### 2의 거듭제곱 찾기 (로그 시간)

다음은 2보다 작은 가장 큰 거듭제곱을 찾는 프로그램이다.

```python
def f(n):
    while n != 0:
        n /= 2
```

매 단계마다 $n$을 2로 나누므로 시간 복잡도는 $O(\log_2 n)$이다. $n$에서 출발해 절반씩 줄여나가는 과정은 반대로 $1$에 $2$를 계속 곱해 $n$을 만드는 과정을 거꾸로 되돌리는 것과 같다. $2$를 $k$번 곱해 $n$이 된다면($2^k = n$) 나눈 횟수 $k$는 $k = \log_2 n$이 된다. 3으로 나누면 $\log_3 n$이 되지만, 빅오 표기법에서는 밑에 관계없이 상수를 무시하므로 두 경우 모두 $O(\log n)$으로 표현한다.

### 부분집합 구하기 (지수 시간)

다음은 주어진 집합의 모든 부분집합을 찾는 프로그램이다.

```python
def find_subsets(arr, n):
    for i in range(0, 1 << n):
        # ...
```

`1 << n`은 비트 시프트 연산으로, 이진수에서 비트를 왼쪽으로 한 칸 밀 때마다 값이 2배씩 늘어나므로(십진수 뒤에 0을 붙이면 10배가 되는 것과 같은 원리) `1`을 왼쪽으로 $n$칸 밀면 $2^n$과 같아진다. 바깥쪽 루프는 $n$개 원소로 만들 수 있는 부분집합의 총개수인 $2^n$번 반복하고, 안쪽에서는 각 부분집합마다 $n$개의 원소가 포함되었는지 비트를 하나씩 확인하므로 $O(n)$이 추가된다. 두 루프가 중첩되어 곱해지므로 전체 시간 복잡도는 $O(2^n \times n)$이다.

### 피보나치 수 (재귀, 메모이제이션, 행렬 거듭제곱)

$n$번째 피보나치 수를 구하는 다음 재귀 함수를 보자.

```python
def fib(n):
    if n <= 1:
        return 1
    return fib(n-1) + fib(n-2)
```

함수 1회 호출 자체는 $O(1)$이지만, 호출할 때마다 두 번씩 재귀 호출이 일어나 트리 구조로 노드 수가 두 배씩 늘어난다. 방정식 $F(n) = F(n-1) + F(n-2)$의 특성 방정식 $x^2 - x - 1 = 0$을 풀면 해가 $x = \frac{1+\sqrt5}{2}$와 $x = \frac{1-\sqrt5}{2}$로 나오고, 선형 재귀 함수의 해가 $F(n) = \left(\frac{1+\sqrt5}{2}\right)^n + \left(\frac{1-\sqrt5}{2}\right)^n$로 주어진다는 사실을 이용하면 $T(n) = O(1.6180^n)$, 즉 지수 시간이 걸린다는 것을 알 수 있다.

이미 계산한 값을 배열에 저장해 두고 재사용하는 메모이제이션(Memoization)을 적용하면 구별되는 상태가 $n$개뿐이므로 각 상태를 한 번씩만 계산하는 선형 시간 $O(n)$으로 줄일 수 있다.

```python
dp = [0, 1]

def fib(n):
    if n < len(dp):
        return dp[n]
    else:
        dp.append(fib(n-1) + fib(n-2))
        return dp[n]
```

피보나치를 행렬 곱셈 형태로 바꾸고 거듭제곱을 반씩 쪼개어 계산하는 분할 정복 기법인 행렬 거듭제곱(Matrix Exponentiation)을 쓰면 시간 복잡도를 $O(\log n)$까지 더 줄일 수 있다.

### 중첩 반복문 (로그 선형 시간)

다음 코드의 시간 복잡도는 얼마일까?

```python
for i in range(1, n):
    for j in range(i, n, i):
        print("hello")
```

바깥 루프 $i$가 $1$부터 $n$까지 증가할 때 안쪽 루프 $j$는 $i$씩 증가하며 실행되므로, $i$가 커질수록 안쪽 루프의 실행 횟수는 $n, \frac{n}{2}, \frac{n}{3}, \dots, 1$로 급격히 줄어든다. 이 실행 횟수를 모두 더하면 $n \times \left(1 + \frac12 + \frac13 + \dots + \frac1n\right)$이 되는데, 괄호 안의 합(조화급수)이 자연로그 $\ln n$에 수렴한다. 따라서 $O(n^2)$처럼 보이지만 실제로는 $O(n \log n)$이다. 같은 원리가 에라토스테네스의 체 같은 알고리즘에도 쓰인다.
